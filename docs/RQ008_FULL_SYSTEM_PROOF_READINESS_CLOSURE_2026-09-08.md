# RQ-008 — Full-System Replay / Out-of-Sample Win-Loss Proof — Readiness Closure — 2026-09-08

Status: CLOSED / `NOT_TESTABLE_WITH_CURRENT_EVIDENCE`

## Decision question

Is the NEXUS XAU research system currently ready for a source-faithful, reproducible full-system replay that can legitimately report canonical trade Win/Loss, expectancy, and out-of-sample performance?

## Decision

```text
NOT_TESTABLE_WITH_CURRENT_EVIDENCE
```

A full-system outcome run was **not** launched because the readiness prerequisites fail before outcome inspection. Running it now would require hidden analyst assumptions and would create a misleading system-level statistic.

This is a methodological closure, not evidence that the trading system has no edge.

## Readiness requirement 1 — complete trade construction

`docs/WIN_LOSS_PROOF_PROTOCOL_2026-09-03.md` requires a canonical trade to have all of the following frozen before final outcome review:

1. valid setup label;
2. entry time and price;
3. SL / loss-invalidation rule;
4. TP / exit rule;
5. replacement / re-entry handling;
6. spread / slippage / cost model;
7. same-bar TP/SL ambiguity handling.

RQ-001 through RQ-007 materially improved the source model but did not close every required field.

### Current source-backed progress

- Post-SIG lifecycle is multi-instance and local to the identified SIG; no global reset assumption.
- PAT2/PAT3 topology and strict `>half` semantics are improved, but exact denominator/tolerances remain parameterized.
- Daily Frame arithmetic and BUY-at-support / SELL-at-resistance semantics are source-backed, but exact location interaction/tolerance and cross-family priority remain incomplete.
- M1/M5 brake is a source-backed zone-first state machine with retest/Entry #2 preference, but force/standing thresholds remain parameterized.
- Sideway lifecycle is source-backed, but exact upper/lower frame and frame-complete geometry remain unresolved.
- Por Chon cutoff/high-selection/persistence semantics are source-backed, while some boundary/standing/priority details remain partial.
- Entry families are source-backed as at least `SIG_ENTRY` and `FRAME_BRAKE_ENTRY`, but there is no single universal SL/exit/invalidation geometry.

### Blocking fields

A universal source-faithful tuple cannot yet be created:

```text
setup
-> exact entry price/time
-> exact SL
-> exact invalidation
-> exact TP/exit
```

without filling material gaps with analyst choices.

Therefore the trade layer of the Win/Loss protocol is not ready.

## Readiness requirement 2 — untouched final out-of-sample period

The project has strong validated M1 price data and previously created conceptual development/validation/test splits.

However, those periods have already been inspected in multiple component, control, relationship, invalidation, re-anchor, and falsification studies. In particular, `docs/OUT_OF_SAMPLE_NEGATIVE_CONTROL_2026-09-03.md` explicitly reports results for development, validation and test periods.

Therefore those historical periods should **not** now be presented as a pristine untouched final holdout for a newly assembled full-system rule set.

They remain valuable for:

- engineering validation;
- source-representation diagnostics;
- negative controls;
- component studies;
- future frozen-rule validation where provenance is stated correctly.

But a future canonical full-system claim should reserve a genuinely untouched period after the executable rule set is frozen.

## Readiness requirement 3 — execution / costs

The project has broker/symbol metadata and can distinguish project reference points from broker points, but a full canonical trade report still needs a frozen execution model appropriate to the tested entry family, including spread/slippage assumptions where relevant.

The current repo does not contain a verified historical deal/order dataset generated by the complete source-faithful system for the required proof period.

Price-path replay remains possible once trade rules are fully frozen, but realized-trade claims must state their execution assumptions explicitly.

## Why existing research statistics are not system Win rate

Existing component outputs include:

- target reach;
- first-hit / symmetric barrier outcomes;
- MFE / MAE;
- topology negative controls;
- Daily Frame relationship studies;
- re-anchor/invalidation studies;
- state-specific diagnostics.

Those are legitimate named research statistics.

They must not be relabeled as `SYSTEM WIN RATE` because they do not represent one fully defined source-backed trade process.

The topology negative control is especially important: large target-hit rates can occur even when the stated topology direction does not beat the matched opposite direction. Therefore `target touched sometime` is not evidence of trade profitability.

## Exact prerequisites to reopen full-system proof

Before RQ-008 should be reopened for an actual outcome run, obtain/freeze at least:

1. **PAT final geometry**
   - PAT1 numeric geometry;
   - PAT2/PAT3 exact 50% denominator and required tolerances or externally labeled deterministic truth.

2. **Location qualification**
   - family-specific PAT-to-frame/zone interaction rule;
   - allowed penetration/tolerance;
   - conflict priority when multiple support/resistance families coexist.

3. **Post-SIG invalidation**
   - exact measurable `กวน/ทำลาย PA` predicate and equality convention.

4. **M5/M1 brake execution**
   - quantitative or externally labeled force/rejection/standing conditions;
   - exact family-specific SL and exit/invalidation logic.

5. **Sideway**
   - deterministic frame bounds/completion/exit geometry if Sideway setups are included in the claimed full system.

6. **Multi-timeframe conflict handling**
   - enough deterministic rules to know when an otherwise valid lower-timeframe entry is invalidated by higher-timeframe state.

7. **Trade-family specification**
   - freeze `SIG_ENTRY`, `FRAME_BRAKE_ENTRY`, and any other included family separately;
   - define entry, SL, TP/exit, re-entry/replacement and cost model for each.

8. **Fresh holdout**
   - reserve a genuinely untouched period only after the executable rule version is frozen;
   - do not tune thresholds on that final period.

9. **Controls and ambiguity handling**
   - matched/random/shuffled controls;
   - non-overlapping/cluster sensitivity;
   - explicit `AMBIGUOUS_SAME_BAR` handling when M1 cannot resolve path order.
